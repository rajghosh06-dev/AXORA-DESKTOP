## Implemented model

- `AppLifecycle` awaits host start and all mandatory pre-activation work before activating the window. Lazy voice/P2P construction is admitted atomically with shutdown, so a constructor cannot start work after shutdown begins and escape tracking. Shutdown does not instantiate unused services. Its cached shutdown task waits for an in-flight startup, operationally stops tracked voice/P2P work, removes the tray, stops the host, and **always attempts host final disposal**. Every step is logged; service and logging failures are aggregated and propagated after remaining cleanup steps. `AppWindow.Closing` cancels the first close request until this task finishes, preserving the dispatcher for asynchronous cleanup, then closes normally.
- Critical startup: XAML initialization, host construction/start, main-window creation, theme initialization, window-handle acquisition, settings resolution, enabled P2P startup, and activation. Failure before activation triggers cleanup, nonzero exit status, and application exit; the ordinary window is not presented as healthy. Tray creation is optional/recoverable and is logged as an attempt; its service now reports a failed native add truthfully and frees a partially loaded icon.
- Global XAML and unobserved-task handlers still log diagnostics, but no longer explicitly mark unknown exceptions handled/observed. `Program.Main` gives its post-dispatcher fallback shutdown a 15-second limit and marks failure/timeout with nonzero exit status; normal window closure completes shutdown before dispatcher teardown.
- DI/Host is the sole final-disposal owner of DI-created services. `VoiceCoordinator.StopAsync` is an idempotent operational stop that prevents restart, cancels and drains its tracked synthesis tasks before DI disposal, detaches its subscriptions once, and does not dispose injected services. Its final `Dispose` releases its own state semaphore and cancellation source when the operational stop has completed. `SpeechSynthesisService.Stop` no longer repeats a native pause when playback has already stopped. `AudioDeviceMonitor` detaches watcher handlers and stops its watcher once; its managed semaphore is intentionally left for GC because an in-flight WinRT query may still release it. `P2pSyncService` serializes start/stop, retains and awaits accept/broadcast/client tasks with a bounded wait, ensures an accepted client is disposed even if cancellation arrives before its handler runs, refuses restart after an incomplete stop, and reports incomplete cleanup instead of silently swallowing it. Tray deletion failure is likewise surfaced. Pairing, encryption, and transfer behavior were not redesigned.

## P3B-R1 AUDIT REPAIR — 2026-09-29

This section amends, rather than replaces, the original P3B record above. The independent P3B code audit found that its broad claim of bounded operational shutdown was not proven for active native voice work, and rejected whole-app fatality for optional P2P startup. R1 repairs only F1, F2, F3, F4 and P2P-M1. All changes remain unstaged; no commit or push was made.

### Corrected lifecycle and ownership policy

- **F1, active voice:** `AppLifecycle.DefaultVoiceStopTimeout` is a named 10-second engineering bound, overridable in lifecycle tests. Shutdown closes new voice admission, asks `VoiceCoordinator.StopAsync()` to cancel/detach/stop and drain its work, and waits at most this bound for the voice stop result. A timeout or other voice-stop failure is an explicit aggregate shutdown failure. The window-close handler then permits final close with a nonzero process exit status; it does not report clean shutdown or force-kill the process.
- **Post-timeout DI safety — rule B:** if voice or P2P operational stop cannot be confirmed, `AppLifecycle` still attempts independent tray cleanup but **postpones host stop and final disposal**. The live DI host remains referenced until process exit so incomplete native tasks cannot resume against already disposed injected services. This intentionally sacrifices clean in-process release on an incomplete stop and reports failure. It is not a universal guarantee that a blocking native call returns within the engineering bound; the bound covers asynchronous stop work after `StopAsync` returns a task.
- **F2, completion callbacks:** callback admission and the stopping flag now share the coordinator's owned-task gate. Playback-completion work is registered before it can escape, checks stopping before and after acquiring the state semaphore, and is drained together with synthesis work before successful operational stop and subsequent DI disposal. A faulted completion task is observed. `VoiceCoordinator` still does not final-dispose injected transcriber, router, audio monitor or synthesizer.
- **F3, optional P2P:** P2P resolution and start are awaited inside `AppLifecycle.StartOptionalP2pAsync`, not launched fire-and-forget. Construction/start failures are recorded and logged as Mobile Link unavailable while shell activation proceeds. Constructed partial P2P remains tracked for later stop; failed resolution creates no fictitious instance. `MobileLinkViewModel` now starts in a truthful starting/not-running state and clears running/QR state on startup failure. The legacy setting default is unchanged; no future Tools settings migration or protocol change was made.
- **F4, tray:** registration and owned HICON state are now separate. Failed `NIM_DELETE` retains both for retry; failed `DestroyIcon` retains the handle after successful delete. Successful removal is idempotent. Failed native add releases a partially loaded icon. A narrow injected native seam supports deterministic ownership tests; production still uses the original Windows APIs.
- **P2P-M1:** a timed-out stop retains outstanding accept/broadcast/client tasks, linked CTS, and key material, clears advertised QR availability, rejects restart, and reports incomplete cleanup. A later `StopAsync` rechecks/drains retained work and only then releases the state. `Dispose` rejects incomplete work without marking the instance disposed, so retry remains possible. A completed client task still awaiting dictionary-removal continuation does not falsely block disposal.

## P3B-R2 FINAL STOP-PATH CLOSURE — 2026-09-29

This section appends the R2 implementation and evidence without rewriting the P3B/R1 history above. R2 addresses the three findings of the independent R1 re-audit: B1 active-send lock contention, B2 voice stop-task publication, and B3 constructor-triggered P2P startup. The coordinated P3B+R1+R2 working set remains unstaged; no commit or push was made.

### Lock, I/O and resource ownership

- `P2pSyncService` now holds `_socketGate` only for short registration, retirement and lease-count updates. Each admitted broadcast takes a lease on every selected socket under that gate, then releases it before any `WebSocket.SendAsync`. A per-socket send semaphore preserves the previous one-send-at-a-time rule without blocking the global collection. The client handler remains the socket's final-disposal owner and waits for its leases to drain before its `using` scope can dispose the WebSocket. A retired socket remains tracked until that drain completes. A failed or disconnected socket is retired through a separate short gate update. No network `await` occurs while `_socketGate` is held.
- Every WebSocket broadcast combines the caller token with the server-lifetime token, so `CancellationToken.None` at the UI call site does not exempt a send from shutdown. The UDP beacon/mDNS sends now also use their server-lifetime cancellation token. Outbound broadcasts are admitted and tracked under the same gate used to close admission; an incomplete broadcast keeps ownership visible to stop/disposal.
- `StopAsync` bounds acquisition of the lifecycle semaphore. Its single named/test-overridable `DefaultBackgroundShutdownTimeout` budget also covers asynchronous cancellation callbacks, owned listener-stop/socket-abort operations, and the accept/broadcast/client/outbound task drains; a stopwatch carries remaining time across phases. Stop closes admission and reserves socket-abort leases before retirement, then requests service cancellation. Synchronous `TcpListener.Stop` and `WebSocket.Abort` run as tracked background operations and are awaited within the same budget, without holding the collection gate or the UI dispatcher. Client handlers perform final socket disposal only after send/abort leases drain. If any cancellation, listener/socket, background/client/send work or socket ownership remains incomplete, stop reports failure and retains CTS/task/key/socket ownership for a later retry. Restart and final disposal remain disallowed while incomplete.

### Startup and voice boundaries

- `AppLifecycle` remains the only automatic legacy-host P2P startup owner. `MobileLinkViewModel` no longer starts `EnsureServerStartedAsync` from its constructor. It observes actual running/QR state; `MobileLinkPage` performs an awaited, read-only state/QR refresh on load. The existing explicit `RestartServerCommand` remains the user-requested retry route. No Tools setting/default or P2P pairing/framing/encryption/ACK behavior was intentionally changed.
- `VoiceCoordinator.StopCoreAsync` closes work/callback admission synchronously, then yields on the calling synchronization context before transcriber or media teardown. This makes `StopAsync` return its owned task to `AppLifecycle` before the known asynchronous WinRT stop wait can run; the existing ten-second lifecycle wait can then observe it, report timeout, and withhold host disposal. It does **not** move WinRT calls to an unproven worker apartment. It is not a universal hard bound on a synchronous native call that itself blocks the UI dispatcher; no such indefinite `ContinuousRecognitionSession.StopAsync` invocation or `MediaPlayer.Pause`/source operation was demonstrated. The precise claim is that all known *asynchronous* voice-stop waits are bounded after task publication while the dispatcher remains responsive.
