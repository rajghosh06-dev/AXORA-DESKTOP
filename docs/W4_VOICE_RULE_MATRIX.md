## 1. Governance & Rule Structure

Every architectural invariant and behavioral requirement within the AXORA Voice Subsystem is codified in this Rule Matrix. Each rule specifies:
- **Rule ID**: Unique deterministic rule identifier (`R-VOICE-XX`).
- **Requirement**: The exact mandatory behavior or constraint.
- **Enforcement Location**: The concrete service, coordinator, or guard where enforcement occurs.
- **Verification Method**: The automated test suite or assertion proving conformance.
- **Failure Behavior**: The deterministic system response if the constraint is violated or platform fails.

## 2. Definitive Voice Rule Matrix

| Rule ID | Requirement | Enforcement Location | Verification Method | Failure Behavior |
|---|---|---|---|---|
| **R-VOICE-01** | **Network Isolation**: Voice services are designed to execute locally without cloud speech services; audio recordings and transcribed text are not transmitted over network sockets. | `VoiceCoordinator`, `VoiceTranscriberService`, `SpeechSynthesisService` | Network observation test verifying 0 TCP/UDP packets emitted during voice processing session. | Hard throw / pipeline abort if socket access is detected during local session; test failure. |
| **R-VOICE-02** | **Ephemeral Audio Buffering**: Microphone audio frames must only exist in volatile memory and be discarded upon completion of recognition. | `VoiceTranscriberService` | Memory diagnostic test observing no audio buffer retention after dictation stop. | Buffer retention diagnostic fails if unmanaged buffers accumulate across start/stop cycles. |
| **R-VOICE-03** | **No Audio File Spooling**: Voice dictation and commands must never create or leave `.wav`, `.pcm`, or `.mp3` temporary files on disk. | `VoiceTranscriberService`, `VoiceCommandRouter` | File-system monitor assertion verifying zero disk I/O in temp and app data directories. | Throw `InvalidOperationException` if disk write is attempted; test suite failure. |
| **R-VOICE-04** | **Acoustic Feedback Gating**: When speech playback is active, microphone listening and continuous dictation must be muted or paused. | `IVoiceCoordinator` (`RequestSpeakAsync`, `_stateLock`) | State coordinator unit test verifying `IsRecording == false` or paused while `IsSpeaking == true`. | TTS request is rejected or microphone is paused automatically before starting audio playback. |
| **R-VOICE-05** | **Configurable Acoustic Debounce**: After speech playback finishes, microphone listening must delay resumption by a configurable gating interval (initial design target: 250 ms) to be validated during runtime testing. | `VoiceCoordinator` (`OnSpeechEnded`, `AcousticDebounceInterval`) | Configurable timing delta assertion in coordinator unit test. | Audio captured during debounce window is discarded to prevent speaker acoustic feedback. |
| **R-VOICE-06** | **Microphone Permission Handling**: Gracefully catch `0x80070005` (`UnauthorizedAccessException`) if Windows mic privacy is disabled. | `AudioDeviceMonitor`, `VoiceTranscriberService` | Unit test throwing mock `UnauthorizedAccessException` on startup. | Transition to `AudioCaptureHealth.PermissionDenied`; show non-intrusive Settings link; no crash. |
| **R-VOICE-07** | **No Microphone Fallback**: If no audio capture device is connected, voice operations must gracefully disable without modal error dialogs. | `AudioDeviceMonitor` (`HasMicrophone`) | Mock device enumerator returning 0 capture devices. | Set `VoiceSessionState.Disabled`; controls disabled with tooltip "No microphone detected". |
| **R-VOICE-08** | **Device Hotplug Recovery**: System must dynamically update capture health when microphones are connected or disconnected at runtime. | `AudioDeviceMonitor` (`DeviceWatcher`) | Hotplug event simulation in integration test. | Update `AudioDeviceStatus`; safely stop active dictation if active device is detached. |
| **R-VOICE-09** | **Command Safety Classification**: Commands must be explicitly classified as `Safe`, `ConfirmationRequired`, or `VoiceProhibited`. Destructive operations must be rejected from direct voice execution. | `VoiceCommandRouter` (`RegisterCommand`, `ExecuteCommandAsync`) | Registry audit test verifying no destructive or unconfirmed actions are marked `Safe`. | Direct execution of `ConfirmationRequired` or `VoiceProhibited` commands throws or rejects; prompt confirmation or abort. |
| **R-VOICE-10** | **Deterministic Command Matching**: Commands must match registered primary phrases or registered aliases exactly after normalization. Ambiguous phrases must not execute an action. | `VoiceCommandRouter` (`MatchCommand`) | Parameterized unit tests with exact, alias, and ambiguous spoken inputs. | Returns `VoiceCommandMatchResult.IsMatched = false`; emits neutral auditory/visual cue; zero action executed. |
| **R-VOICE-11** | **Command Normalization**: Spoken command input must be whitespace-trimmed, lowercase-normalized, and punctuation-stripped deterministically before matching. | `VoiceCommandRouter` (`NormalizePhrase`) | Parameterized unit tests with erratic casings, extra spaces, and trailing symbols. | Un-normalized match fails; normalized input matches intended target deterministically. |
| **R-VOICE-12** | **Dictation Punctuation Commands**: Spoken keywords ("period", "comma", "new line", "new paragraph") must convert to appropriate punctuation. | `VoiceTextFormatter` (`ApplyPunctuationCommands`) | Formatting unit test verifying string transformations across sample spoken corpora. | Unmatched terms remain literal text; matched terms replace cleanly without trailing spaces. |
| **R-VOICE-13** | **Disfluency Suppression**: Conversational fillers ("um", "uh", "ah") occurring as isolated tokens must be stripped from dictated notes. | `VoiceTextFormatter` (`CleanDisfluencies`) | Unit test passing text containing conversational fillers. | Strips isolated filler tokens while preserving legitimate words (e.g. "umbrella"). |
| **R-VOICE-14** | **Deterministic WinRT Disposal**: Every `SpeechRecognizer` instance must be explicitly disposed before a new one is allocated. | `VoiceTranscriberService` (`StartDictationAsync`) | Handle diagnostic test executing 50 rapid start/stop cycles. | Recognizer is cleaned up; no WinRT native audio handle accumulation occurs. |
| **R-VOICE-15** | **Speech Synthesizer Pitch/Rate Clamping**: TTS rate must clamp strictly to `[0.5, 3.0]` and pitch to `[0.5, 1.5]`. | `SpeechSynthesisService` (`SpeakTextAsync`) | Boundary unit test with out-of-range rates (-1.0, 10.0) and pitches (-2.0, 5.0). | Clamps to safe boundary values; prevents native speech engine crashes. |
| **R-VOICE-16** | **Empty Speech Text Guard**: Calling `SpeakTextAsync` with null, empty, or whitespace-only text must be an immediate no-op. | `SpeechSynthesisService` (`SpeakTextAsync`) | Unit test with `""`, `null`, `"   "`. | Returns `Task.CompletedTask` immediately without allocating synthesizer stream. |
| **R-VOICE-17** | **Concurrent Speak Serialization**: Overlapping `SpeakTextAsync` calls must be serialized via lock or cancel the preceding utterance cleanly. | `SpeechSynthesisService` (`_speakLock`) | Concurrency test firing 10 parallel `SpeakTextAsync` tasks. | Preceding utterance stops; latest utterance plays cleanly; zero overlapping audio output. |
| **R-VOICE-18** | **Non-Blocking UI Execution**: All speech recognition and synthesis tasks must execute asynchronously off the UI thread. | `VoiceCoordinator`, `VoiceTranscriberService` | Dispatcher queue test asserting UI thread responsiveness during heavy speech operations. | Offloaded to background tasks; WinUI UI thread frame rendering remains responsive. |
| **R-VOICE-19** | **UI Event Thread Marshalling**: All voice events dispatched to ViewModels/Views must be marshalled to the UI DispatcherQueue. | `VoiceCoordinator`, `VoiceTranscriberService` | Multi-threaded event invocation test verifying `DispatcherQueue.TryEnqueue` call. | Cross-thread violation if unmarshalled; caught and handled by dispatcher helper. |
| **R-VOICE-20** | **Log Redaction**: User dictation sentences and academic note text must NEVER appear in application logs (`ILogger`). | All voice services (`VoiceTranscriberService`, etc.) | Log interceptor test validating zero dictated strings appear in written log output. | Only metadata (char length, command ID, error code) is logged; user text is strictly redacted. |
| **R-VOICE-21** | **Process Shutdown Cancellation**: When the application window closes, all active voice capture and speech playback must cancel promptly. | `App.xaml.cs`, `MainWindow.cs` (`Closed`) | App shutdown simulation test verifying cancellation token trigger and service disposal. | `CancellationTokenSource.Cancel()` called; playback halts promptly; devices released. |
| **R-VOICE-22** | **Speech Language Pack Prerequisite**: If Windows dictation language pack is unavailable, system must degrade to command recognition where supported. | `VoiceTranscriberService` (`CompileConstraintsAsync`) | Unit test mocking dictation compilation failure. | Surfacing non-fatal alert; voice navigation commands remain functional where supported. |
| **R-VOICE-23** | **Voice Settings Round-Trip**: Voice preferences (voice ID, speech rate, pitch, voice navigation) must persist and restore accurately. | `SettingsViewModel`, `IAppSettingsService` | Serialization round-trip unit test verifying save and restore from settings JSON. | Restores previous values; falls back to default voice if configured voice is uninstalled. |
| **R-VOICE-24** | **W3-F Component Immutability**: Implementing W4 must not modify or alter any W3-F synthesis, grounding, or indexing services. | Build & Git inspection | Git diff validation against W3-F baseline commit `2e8eb83`. | Zero modified lines in W3-F production code files. |
