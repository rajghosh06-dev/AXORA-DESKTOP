## 1. Purpose & Scope

Phase **W3-C.6.3** establishes the structural text normalization and paragraph assembly layer of the AXORA Scholar Kit document extraction pipeline. Building upon the character-level sanitization and Unicode normalization foundation completed in Phases W3-C.6.1 and W3-C.6.2, Phase W3-C.6.3 governs how raw extracted text lines are assembled into coherent semantic paragraphs, how visual line-wrapping is resolved in fixed-layout and scanned documents, how line-break hyphenation is safely handled, how DOCX structural Markdown scaffolding is reconciled, and how code blocks and tabular structures are protected.

### 1.1 Strict Scope Boundaries

#### IN SCOPE for W3-C.6.3:
1. **Source-Format-Aware Structural Normalization**:
   - Differentiating structural text behavior across all 10 supported formats (`PlainText`, `Markdown`, `DelimitedText`, `LocalHtml`, `PdfDigital`, `PdfScanned`, `PdfMixed`, `Docx`, `RasterImage`, `MultiPageTiff`).
2. **Deterministic Paragraph Assembly**:
   - Standardizing paragraph breaks into canonical `\n\n` boundaries when justified by clear structural evidence.
   - Preserving headings (`# `), list items (`- `, `* `, `\d+\. `), blockquotes (`> `), and tables (`|`).
   - Normalizing whitespace surrounding block-level elements.
3. **PDF Digital Soft-Line Wrap Rejoining**:
   - Resolving typographical line breaks emitted by PDF content stream operators (`Td`, `TD`, `T*`, `'`, `"`, `ET`) into flowing paragraph text with space delimiters.
   - Distinguishing soft wraps from intentional paragraph breaks using a conservative, evidence-based line classification policy.
   - Ambiguity rule: when evidence of paragraph termination or continuation is ambiguous, the newline (`\n`) is preserved.
4. **Restricted OCR Line Fragmentation & Spacing Correction**:
   - Rejoining fragmented lines generated by `WindowsMediaOcrEngine` in `PdfScanned`, `PdfMixed` OCR pages, `RasterImage`, and `MultiPageTiff`.
   - Performing narrowly scoped, deterministic OCR spacing correction before commas and periods on alphabetic words while excluding code, math, URLs, identifiers, and brackets.
5. **Conservative Line-Break Hyphenation Repair**:
   - Governing the repair of words split across lines by discretionary line-end hyphens (`algo-\nrithm` $\to$ `algorithm`).
   - Default setting: `RepairLinebreakHyphenation = false`.
   - When explicitly enabled, applying strict condition gates to prevent altering scientific identifiers (`α-helix`, `Na-Cl`, `p-value`, `state-of-the-art`, `well-known`).
6. **DOCX Structural Markdown Token Reconciliation**:
   - Normalizing structural markers emitted by `DocxDocumentExtractorEngine` during Phase W3-C.4.
   - Compacting consecutive list item paragraphs to single newlines (`\n`).
   - Ensuring headings and tables possess proper bounding newlines without removing author-supplied Markdown.
   - Preserving text when intent or structure cannot be deterministically established.
7. **Protected Code Region Preservation**:
   - Detecting fenced code blocks (```` ``` ```` or `~~~`) in Markdown and PlainText.
   - Performing no structural rewriting inside recognized protected code regions (preserving indentation, line breaks, and whitespace as derived from C6.2).
8. **Page-Bounded Provenance & Immutability**:
   - Executing strictly within the boundaries of each individual `ExtractedPageRaw`.
   - `ExtractedPageRaw.RawText` remains strictly immutable.
   - Text is **never** concatenated across distinct physical page boundaries.

#### EXPLICITLY OUT OF SCOPE for W3-C.6.3:
1. **Passage Chunking**: Slicing normalized text into fixed-size windows with stride overlap (e.g. 350-character chunks with 60-character overlap) is strictly owned by **Phase W3-C.7 (`IPassageChunker`)**. Paragraph assembly does NOT produce passage chunks.
2. **Cross-Page Line Concatenation**: C6.3 does **not** concatenate text across physical page boundaries. If page $N$ ends mid-sentence or mid-word and page $N+1$ continues it, each page retains its local segment. Cross-page text bridging is deferred to chunking/provenance retrieval.
3. **Generative / Neural Rewriting**: No large language models (LLMs), small language models (SLMs), neural spell-checkers, or semantic restructuring engines. Normalization is strictly deterministic, rules-based C# code.
4. **Network / Cloud Operations**: Zero network calls, zero cloud dependencies, zero external APIs.

## 2. Core Engineering Invariants

### Invariant 1: Immutability of Ground Truth RawText
- `ExtractedPageRaw.RawText` is the forensic ground truth discovered by the format-specific extractor.
- `RawText` **MUST NEVER** be mutated, re-encoded, truncated, or overwritten.
- `NormalizedText` is a derived property computed by `ITextNormalizer`.
- Assertion: `normalizedPage.RawText == rawPage.RawText` must hold unconditionally across all operations.

### Invariant 2: Page-Bounded Execution & Provenance Isolation
- Normalization operates strictly page-by-page on `ExtractedPageRaw`.
- Page boundaries are never merged, erased, or synthesized.
- All page geometry (`WidthPt`, `HeightPt`), page semantics (`PhysicalPage` vs `LogicalSection`), OCR flags (`ExtractedViaOcr`), and confidence ratings (`Confidence`) are preserved intact.
- Physical page numbers (1-indexed) are strictly preserved.
- **Cross-Page Invariant**: Under no circumstances may text from Page $N$ be joined into Page $N+1$.

### Invariant 3: Scientific, Mathematical & Chemical Invariant Protection
The following notations are protected against structural degradation under tested normalization rules:
- **Mathematical Superscripts & Subscripts**: $x^2$, $y^2$, $10^{-3}$, $e^{\pi i}$, $\text{H}_2\text{O}$, $\text{CO}_2$, $\text{C}_6\text{H}_{12}\text{O}_6$, $\text{Fe}^{2+}$.
- **Greek Variables**: $\alpha, \beta, \gamma, \Delta, \theta, \lambda, \mu, \sigma, \omega$.
- **Mathematical Operators**: $\int, \sum, \prod, \sqrt{}, \le, \ge, \ne, \approx, \pm, \infty, \nabla$.
- **Hyphenated Scientific Terms**: `α-helix`, `Na-Cl`, `p-value`, `R-squared`, `cis-trans`.
- **LaTeX Delimiters**: `$E = mc^2$`, `$$\int f(x) dx$$`.
- **Chemical Reactions**: $\rightarrow, \rightleftharpoons, \leftrightarrow$.

### Invariant 4: Strict Determinism & Bounded Idempotence
- **Determinism**: For any input string $x$, format $F$, and options $O$, `Normalize(x, F, O)` must yield bit-for-bit identical ordinal strings across all runs, threads, and platforms.
- **Idempotence**: 
  $$\operatorname{Normalize}(\operatorname{Normalize}(x, F, O), F, O) == \operatorname{Normalize}(x, F, O)$$
  Re-running normalization over already normalized structural text produces zero drift. In the presence of malformed structures (e.g. unclosed code fences), the parser maintains identical deterministic bounds across repeated passes.

### Invariant 5: Fault Isolation & Exception Resilience
- `ArgumentNullException.ThrowIfNull` on null text or page inputs.
- `OperationCanceledException` is **never** swallowed; it is immediately rethrown.
- Unhandled extraction or formatting exceptions during page normalization fall back to `NormalizedText = rawText` and append `ERR_NORMALIZATION_FAILED: {ex.Message}` to `DiagnosticWarning`.
- Zero document text is logged to disk or console.

## 3. Paragraph Assembly Product Model

In AXORA Scholar Kit, the structural representation of normalized text adheres to the following definitions:

| Element | Definition | Canonical Representation in `NormalizedText` |
| :--- | :--- | :--- |
| **Paragraph Break** | Boundary separating two distinct narrative or logical blocks | Exactly two line breaks: `\n\n` |
| **Flowing Line Wrap** | Visual wrap within a single narrative paragraph (PDF/OCR) | Joined with a single ASCII space: `' '` |
| **Heading** | Structural section title (`# `, `## `, `### `, etc.) | Bounded by `\n\n` before and after; single space after hashes |
| **List Item** | Bullet or numbered item (`- `, `* `, `1. `) | Single newline `\n` between consecutive items; `\n\n` around list block |
| **Table Row** | Tabular row demarcated by pipes (`\| Col 1 \| Col 2 \|`) | Single newline `\n` between table rows; `\n\n` around table block |
| **Protected Code Region**| Fenced program code or preformatted ASCII block | No structural rewriting; preserved as derived from C6.2 |
| **Blockquote** | Quoted passage demarcated by `> ` | Single newline between quote lines; `\n\n` around quote |
| **Ambiguous Line Break**| Line break where paragraph intent cannot be proven | Single newline `\n` preserved (conservative preservation) |

## 4. Options Contract & Defaults Reconciliation

The `TextNormalizationOptions` record established in Phase W3-C.6.1 governs C6.3 execution:

```csharp
public sealed record TextNormalizationOptions
{
    // Tier A: Artifact-Preserving Cleanup (Implemented in C6.2)
    public bool NormalizeLineEndings { get; init; } = true;
    public bool StripNonPrintableControlChars { get; init; } = true;
    public bool StripBOMAndZeroWidthChars { get; init; } = true;

    // Tier B: Formatting Standardizations (Active in C6.3)
    public bool CollapseConsecutiveSpaces { get; init; } = true;
    public bool PreserveParagraphBreaks { get; init; } = true;

    // Tier C: Optional Glyphic Transformations (C6.2 & C6.3)
    public bool ApplyUnicodeNfkc { get; init; } = false;
    public bool UnfoldTypesettingLigatures { get; init; } = true;
    public bool RepairLinebreakHyphenation { get; init; } = false;
}
```

### 4.1 Options Behavior in C6.3:
1. **`PreserveParagraphBreaks = true` (Default)**:
   - Delineates paragraphs with `\n\n` when supported by structural evidence.
   - Protects headings, lists, tables, and blank lines.
   - If `false`, merges paragraphs across blank lines into continuous flowing text (compacting mode).
2. **`CollapseConsecutiveSpaces = true` (Default)**:
   - Collapses runs of $\ge 2$ spaces/tabs on a single line to a single space, **except** inside protected code regions and leading paragraph indentations ($\le 4$ spaces).
3. **`RepairLinebreakHyphenation = false` (Default)**:
   - Preserves line-end hyphens (`word-\nbreak` $\to$ `word-\nbreak` or `word-break`).
   - If explicitly set to `true`, applies conservative condition gates to rejoin broken word stems (`computa-\ntion` $\to$ `computation`) while strictly protecting chemical formulas, single-letter prefixes, proper names, and math expressions.
